# HDMap 전역 기하·정지선 데이터 감사

이 문서는 2026-09-05 수정 전 지도에 대해 독립적으로 수행한 데이터 감사다. 원본 모든 driving laneSection의 구간 보존과 생성된 lanelet/cell의 내부 기하는 통과했지만, **정지선 원본 객체 중복·OSGB 도색과의 위치 불일치·일부 접근 차로 정지선 누락**을 발견했다. 내부 polygon 검사가 통과한다고 도로 현장 의미나 신호 대응이 맞는 것은 아니다.

수정 후 지도에 이 수치를 그대로 적용하지 않는다. 이 감사의 기준 바이너리는 SHA-256 `7759de6a84ba9ef6fd7807792c642d5e479a981c37cbc38f570fc4912420bc78`이다. 후속 수정/재생성 결과는 별도 검사를 해야 한다. 이 담당 작업에서는 지도 생성 코드, 원본 자료, config를 변경하지 않았다.

## 자료와 방법

- 원본: `/home/stier/vtd 자료/HL_FMA_VTD_LivingLab.xodr`, `.osgb`.
- 생성 지도: `map/hdmap.bin`, `map/build_report.json`.
- OSGB 도색 후보: `map/stopline_mesh.json`의 689개 직사각형.
- 추출 전 흰색 삼각형: `/tmp/hdmap-white-triangles.txt`.
- native C++ 로드·R-tree·routing 검사와 Python Lanelet2 로드를 각각 실행했다. Python은 `/opt/ros/jazzy`의 실제 설치된 바인딩, C++ 실행 파일은 기존 `/tmp/hdmap-map-check/hdmap_check`를 사용했다.
- 원본 `(road, laneSection index, lane id)` 및 모든 s 구간을 비교했다. `lane id=0`은 폭이 없는 기준선이므로 자동차 차로 집계에서 제외했다.
- 모든 lanelet/cell polygon 유효성, 부모별 cell 합집합과 중복 면적, cell 순서, `previous` 공간 연결을 검사했다.
- `following(..., false)`와 차로 변경을 포함한 `following(..., true)` 양쪽 native 그래프를 조사했다. 방향 그래프의 단절을 바로 원본 오류로 판정하지 않았다.

## 전역 연결과 극소폭 차로

차로 변경을 제외한 native forward edge는 2,868개이고, 차로 변경을 포함하면 5,416개다. 약연결 성분은 차로 변경 포함 시 2,846개 + 1개 lanelet이다. 가장 큰 강연결 성분은 2,663개다. 방향·차로 변경 금지·지도 끝·taper로 인해 강연결 성분이 하나가 아닌 것은 그 자체로 오류가 아니다.

유일한 독립 lanelet은 `410621`: road 2810, section 5, lane +1, s113.800999993–115.500999994, 중심 약 (1187, 576)이다. 최대 폭은 **0.01913m**이고, 원본 link는 비어 있으며 황색 실선이다. 원본 시각 확인에서도 차로 전환/중앙 도색 구간이다. 정상 도로가 빠져 있다는 이유로 이 작은 잔여 영역을 다른 차로에 연결하면 안 된다.

road 2816 section 2 lane +1 (`430703`)도 최대 폭 약 **0.000721m**다. 이는 차량이 단독 주행할 수 있는 lanelet이 아니다. `/tmp/hdmap-audit/narrow_lanelets.json`에 최대 폭 1m 미만 구간 24개를 기록했다. 상당수는 정상 차로가 열리고 닫히는 taper의 일부이므로 폭 임계값으로 전부 삭제하는 방식도 피해야 한다.

## 정지선 대조: 내부 할당과 실제 도색을 구분

722개 정지선 중 26개는 cell 미할당이다. cell에 할당된 선과 해당 cell의 거리 검사에서 2cm를 초과한 것은 기존 OSGB 보강 12개뿐이며, 각각 약 0.149m다. 이는 geometry를 옮기지 않고 도로 끝 cell에 투영한 기존 정책과 일치한다. 다른 할당 정지선의 방향/공간 교차 검사는 통과했다.

그러나 이 검사는 **잘못된 위치의 정지선을 같은 잘못된 위치의 cell에 붙여도 통과**한다. 따라서 OSGB와 별도로 대조했다.

### OSGB 직사각형 전수 매칭

689개 후보 각각에 중심 XYZ, 장축 방향, 길이를 계산했다. 각 지도 정지선에 대해 최근접 후보와 다음 조건을 모두 만족하는 후보 중 최근접을 따로 기록했다.

- 고도 차이 < 0.6m.
- 무방향 장축 각도 차이 < 10도.
- 길이 차이 < 0.8m.
- 근접 일치 판정: 중심 XY 거리 < 1m.

이 숫자는 감사용 후보 분류 조건이며 자동 수정 허용 범위가 아니다. 다른 교차로의 호환 후보가 가장 가까워도 수십~수백 m 떨어지면 대응 정지선이라고 주장할 수 없다.

도색 후보가 다음 junction 연결 lanelet의 시작에도 걸치는 경우, 교차로 내부 차로를 정지선 접근 차로로 선택하지 않는다. 양쪽 방향에 가까운 후보를 “최근접”만으로 옮기지도 않는다. source object와 OSGB 후보의 동일성이 미확정이면 원본 ID를 바꿔치기하지 않는다.

## 산출물 및 재현

전수 감사의 주 도구를 저장소에 보존했다. `--map-dir`은 `hdmap.bin`과 `build_report.json`이 함께 있는 디렉터리다. 기하 검사는 `--xodr`, 정지선 검사는 `--mesh`로 원본을 지정하고, 두 CLI 모두 `--output`으로 JSON 결과 파일을 명시한다. 원본 지도/report SHA가 일치하지 않으면 중단한다.

결과의 `provenance`에는 실제 입력과 검사 스크립트의 절대 경로·SHA-256, Python 버전, Lanelet2 모듈 경로, NumPy/Shapely/NetworkX 버전이 포함된다. 검사 로직과 원본을 함께 보관하면 임시 작업 디렉터리에 의존하지 않고 재실행할 수 있다. 기본 실행은 발견 사항을 기록하며, 종료 코드 0을 지도 무결점 인증으로 해석하지 않는다.

| 저장소 도구 | 내용 |
|---|---|
| [audit_geometry.py](../map/tools/audit_geometry.py) | 모든 source driving s 구간, lanelet/cell polygon, cell 합집합, native routing 전수 검사 |
| [audit_stoplines.py](../map/tools/audit_stoplines.py) | 모든 stop와 OSGB mesh 후보 위치/고도/방향/길이 매칭 |

```bash
cd /home/stier/HL-FMA2026-sim-stier
source /opt/ros/jazzy/setup.bash
/tmp/hdmap-map-check/hdmap_check map/hdmap.bin '/home/stier/vtd 자료/route_example.csv'
/tmp/hdmap-build-env/bin/python map/tools/audit_geometry.py \
    --map-dir map --xodr '/home/stier/vtd 자료/HL_FMA_VTD_LivingLab.xodr' \

/tmp/hdmap-build-env/bin/python map/tools/audit_stoplines.py \
    --map-dir map --mesh map/stopline_mesh.json \

```

Python 실행 파일 경로는 기존 CommonRoad/NumPy/Shapely 감사 환경의 예다. 같은 의존성과 Lanelet2 바인딩을 제공하는 환경에서도 실행할 수 있다. C++ 검사 도구 빌드 방법은 [정적 지도 문서](06-static-map.md)의 검사 절을 따른다.

이전 감사와 **동일한 지도**에서 이식/실행 재현성을 검증할 때는 각 CLI에 `--baseline saved-audit.json`을 추가한다. provenance를 제외한 모든 결과 필드를 비교하고, 차이가 있으면 assertion으로 실패한다. 지도 수정 후에는 과거 JSON과 의도적으로 달라질 수 있으므로 이 옵션을 통과 기준으로 사용하지 않는다. 최초 CLI 보존 검증은 수정 전 SHA `7759de6a…` 바이너리와 기존 JSON을 이용했다.

이 문서의 수정 전 조사 자료는 이번 세션에서 다음 경로에 보관했다. 이는 과거 관측을 추적하기 위한 보조 자료이며 새 검사의 필수 입력이 아니다. `/tmp`는 영구 보관 위치가 아니므로 필요 시 따로 보존해야 한다.

| 세션 자료 | 내용 |

최초 로컬 native 검사는 로드 약 2.49초, checkpoint 경유 경로 계산 평균 약 0.0287ms였다. 이는 이 실행 환경과 예제 경로만의 측정이며 전역 실제 차량 주행 결과가 아니다.

이번 담당 감사는 정적 데이터와 제한된 원본 이미지 검토다. 전체 simulator 도로 주행, 신호 상태 전이 및 제동, 한국 교통법규와 모든 movement의 합법성을 확인한 것으로 간주하지 않는다. source·변환기·native graph·visualizer·차량 거동을 각각 대조해야 한다.
