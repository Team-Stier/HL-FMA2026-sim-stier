# 적용 결과와 남은 문제

2026-09-11. 직전 설계의 **5번(새 trajectory 메시지 추가)은 제외**했다. 변경 패키지는 `path_planner`, `control`, `hdmap_dynamic_tracker`, `speed_annotator`다. 기존 ROS 메시지로 통신하며 다른 실행 패키지의 소스·라이브러리를 가져오는 의존성은 추가하지 않았다. `interfaces`·`hdmap` 외 프로젝트 패키지 간 새 의존성은 없다. 기존 visualization 작업은 해시로 보존을 확인했다.

## 적용한 코드

- **reference 구성:** lanelet 개수 대신 필요한 전방 거리와 뒤차체 여유를 확보한다. 실제 route의 연결·진행 이력만 사용하고 reference별 허용 차선을 둔다. 차선 변경은 기존 정렬 조건과 route 연결을 유지한다.
- **비용:** 중간 lanelet 끝점까지의 거리 대신 공통 route의 진행량·횡오차·방향을 평가한다. 최종 checkpoint XY만 실제 종단 목표로 사용한다.
- **기하:** 설치된 Boost spline으로 XY/Z 기준선을 만들고 같은 곡선에서 투영·직접 공간 샘플링·곡률을 계산한다. 미래 높이와 전체 차체의 도로 포함을 검사한다. 차로 유지의 횡복귀 거리와 전체 경로 길이를 분리했다.
- **계산량:** 충돌로 잘릴 수 있는 모든 유효 prefix를 고려한 비용 하한으로 후보를 건너뛴다. 하한으로 안전하게 제외하지 못한 후보는 기존 속도·점유·도로 검사를 수행한다.
- **입력·리스폰:** planner와 annotator는 원본 stamp가 같은 ego/dynamic을 사용한다. planner는 단일 계획 timer에서 갱신한다. 위치·높이·방향·시간의 불연속 때 tracker의 속도/예측 이력과 오래된 계산을 폐기하고 새 위치에서 route를 탐색한다. 무효·무경로 출력은 이전 실행 경로를 즉시 해제한다.
- **제어:** stale/invalid/MPC 실패 시 최대 조향·8m/s 전진 fallback을 제거했다. 실제 발행 조향에 공통 각도·변화율 제한을 적용하며 MPC도 그 값을 이어받는다. MPC의 시간 간격은 `v*dt`로 처리하고 곡률 계산용 공간 간격과 분리한다. 짧은 경로에서는 정지한다.
- **속도 상한:** tracker의 제동+지연 기반 감속 역산을 보수적으로 맞췄다. annotator는 오래된 cap을 새 데이터처럼 반복 발행하지 않는다. 추가로 실제 강제 제동 가속도와 longitudinal 내부 변화율 상태의 불일치를 발견해 수정·검증했다.

## 경로 길이 회귀

[최종 31개 표본 비교](final_replay_comparison.json)의 짧은 successor 표본 6개는 기존 **14.99 / 7.99 / 6.42 / 4.13 / 2.14 / 14.41m → 모두 약50m**다. 긴 유효 후보가 비용 때문에 밀리던 3개 표본도 15.79 / 14.10 / 11.32m에서 약50m가 됐다.

31개 중 새 결과가 모두 유효한 것은 아니다. 기존 유효23/무경로8에서 변경 후 유효20/무경로11이다. 이미 도로를 벗어난 입력과 정지 ETA 문제는 포함 검사 완화로 통과시키지 않았다. 이 집계만으로 개선률을 계산하면 안 된다.

최종 planner revision8의 pruning과 전수 계산은 **31/31 입력, 총4,607 pose의 XYZ·quaternion이 정확히 동일**했다. 무경로11개도 같다. 검사 통과 후보 합계는264→40, 한 번의 재생 중앙 계산 시간은48.58→20.40ms였다. 이는 정식 성능 벤치마크가 아니다. 재생에는 원래 기록에 없는 최종 checkpoint XY와 차선 변경 의도가 없으므로 해당 상황은 별도 단위 검사와 실주행으로 구분했다. [대조 결과](pruning/summary.json)

## 실제 주행에서 확인한 것

북쪽 커브, 남쪽 커브, 서쪽 내리막, 북쪽 오르막/신호, 서쪽 교차로와 재시험을 수행했다. 임시 체크포인트는 `/tmp`에 별도로 만들었다. [조작 시각](actions.jsonl), [주행 요약](live_summary.json), 압축된 관측 기록 `events.jsonl.gz`를 보존했다. 선택한 동기 입력과 임시 재생 코드는 `reproduction_bundle.tar.gz`에 있다.

- **신호217:** 적색으로 바뀐 시점의 속도10.46m/s, 앞차축 기준 정지선 거리35.71m였다. 정지선 약12.08m 전에 정지했고 녹색 후 출발해 통과했다. 정지/재출발은 확인됐지만, 정지 ETA 때문에 경로가 비는 현상과 보수적인 조기 정지는 남아 있다.
- **도달 가능한 위치의 리스폰:** 노드 재시작 없이 `2534` 차선으로 이동한 뒤 새로운 글로벌 경로는29.92ms, 로컬 경로는117.68ms 만에 수신됐다. 새 ego의 속도는0으로 시작했다. 시간은 관측기 수신 시각 기준이다. [측정](respawn_reachable_verification.json)
- **도달 불가능한 위치의 리스폰:** `528793`에서 기존 목표`7355`까지 native routing graph가 연결되지 않았다. 위치·높이·방향은 정상 일치했고 기존 글로벌 경로는 약19ms에 지워졌다. 이 경우 새 글로벌 경로가 없는 것은 오래된 route 유지가 아니라 도달 불가다. [근거](respawn_route_findings.md)
- **보호구역:** cap8m/s 전달과 제어 반영을 확인했다. 재시험의 순간9.068m/s는 약0.299m 이동을32.93ms로 나눈 값이고 다음47.38ms 표본은6.315m/s였다. 200ms 평균은7.482m/s여서 실제 급가속이라고 판단하지 않았다. 다만 이 속도 튐에 반응한 강제 제동 뒤 곧바로 가속하는 내부 상태 결함이 드러나 추가 수정했다. 이번 시험만으로 보호구역 진입 전 선행 감속까지 검증 완료했다고 볼 수 없다.

## 아직 해결되지 않은 원인

**커브의 실제 도로 이탈은 남아 있다.** 북쪽 첫 시험은 경로가 비기 전 최신 경로에 대한 제어 횡오차가 최대2.30cm였지만 고정 도로 기준 횡오차는 약44cm까지 누적됐다. 횡복귀 거리를 줄인 재시험도 최신 경로 기준 최대8.15mm/0.302°인 동안 도로 기준 약38.4cm까지 밀렸다. 새 경로가 매번 현재 ego 오차를 시작 조건으로 받아들이기 때문에 최신 경로를 잘 따라간다는 사실만으로 도로 중심을 잘 따라간다고 할 수 없다.

재시험 첫 빈 Path의 ego `(830.273926,-63.461216)`에서는 **15개 후보 모두 현재 차체(index0)의 허용 차로 포함 검사에서 탈락**했다. 지도 cell은6개 있었고 곡률0.01050/m는 한도0.16949/m 이내였다. 따라서 이 최초 무경로는 짧은 reference나 높이 조회 실패가 아니라 이미 차체 일부가 도로 밖으로 간 결과다. 직전 선택 경로는47.69m로 충분히 길었으나 현재 횡오차−0.350m에서2m 앞−0.402m,5m 앞−0.435m로 먼저 더 바깥쪽을 향했다. [정적 기하 재생](recovery_geometry/findings.md)

전체 주행 차선의 합집합을 검사한 독립 scan도 같은 첫 표본에서 오른쪽 앞 모서리의 이탈을 확인했다. 제동 중 마지막 이동 표본에서는 차체 면적의 약39.1%가 도로 밖에 있고 오른쪽 두 모서리가 벗어났다. 따라서 허용 차선 선택만의 오검출로 설명되지는 않는다. [도로 포함 검사](north_recovery_coverage_summary.json)

별도의 물리 응답 분석에서는 `yaw_rate / (v*tan(command)/2.944)`가 지연 보정 후 저속2–4m/s 약0.99에서7–8m/s 약0.83으로 줄었다. 명령 단위와 wheelbase는 일치했다. 실제 바퀴각이 없어 액추에이터와 타이어 효과를 분리할 수 없으며, 임의 고정 gain이나 잘못된 wheelbase로 보정하지 않았다. 경로 재계획의 오차 흡수와 속도별 실제 응답 차이를 함께 다뤄야 한다. [분석](steering_response_findings.md)

추가 한계:

- MPC의400회 반복 한도 실패가 일부 직선/내리막 시험에서 남았다. 이때 전진 fallback 대신 제동하는 것은 검증됐다.
- 위치 메시지의 시간 간격 흔들림이 단일 frame 속도 추정과 overspeed 판단을 흔든다. 이번에는 출력 가속도 상태의 불일치를 수정했으며 원천 시간 동기·속도 추정의 평활화까지 바꾸지는 않았다.
- 새 메시지 추가를 제외했으므로 planner의 점별 속도·ETA를 controller에 온전히 전달하는 계약은 없다. `Float32` 상한은 source stamp를 담지 못한다. `pose.z`에 속도를 숨기거나 다른 패키지 내부를 참조하는 우회는 쓰지 않았다.

## 자동 검토로 보류된 수정

`VelocityPlanner`의 첫0-cap 이전 절단, 정지점까지 유한 ETA 적분, 정지 상태의 one-point HOLD 생성은 **적용되지 않았다**. 기존 전후방 속도 전파·`stop_at_end`·ETA 계산은 원본 그대로다. controller의 one-point HOLD 수신 준비와 planner의 HOLD 생성은 별개다.

자동 승인 검토가 이 편집을 더 이전 권고의5번(속도·정지 처리)에 해당한다고 판단해 거절했다. 직전 설계의5번이 새 메시지 추가라는 대화 근거로 재검토를 요청했지만 다시 거절됐다. 거절된 편집을 다른 방법으로 적용하지 않았다.

검토할 구체안은 [코드 설계안의 VelocityPlanner 변경](../code_change_plan.md)에 있다. 최소 변경 대상은 `VelocityPlanner::plan`, 공용 `resize`, `FrenetPlanner::tick`, 정지 footprint 점유 검사의 `CollisionValidator::firstCollision`이다. 새 메시지를 추가하지 않고 기존 Path의 empty-invalid/one-point-HOLD 표현을 사용한다. 이 부분은 별도 명시 확인 후 적용할 수 있다.


## 빌드·검사·종료 상태

- `path_planner`: colcon 빌드·설치 및 `cost_check` 통과.
- `control`: CMake 빌드·설치, core/실제 노드 검사2개 통과. 마지막 강제 제동 복귀 회귀는 수정 전 실패·수정 후 통과를 확인했다.
- `hdmap_dynamic_tracker`: CMake 빌드·설치, core 검사 통과. 제동 역산 테이블과 리스폰 속도/높이/방향/시간 입력을 검사한다.
- `speed_annotator`: CMake 빌드·설치, 별도 ROS domain의 실제 노드 검사 통과. 양방향 입력 도착 순서·과거/무효 입력의 상한 재활성화 방지를 포함한다.
- 최종 CTest 합계5개 통과, `git diff --check` 통과. 검사 로그는 `tests/`에 보존했다.
- 통합 colcon 명령은 컴파일 전에 기존 `install/hdmap_core/share/hdmap_core/package.sh` 부재로 중단됐다. 해당 설치 파일을 임의로 만들지 않고 이미 구성된 CMake 빌드/설치로 나머지 패키지를 검증했다.
- `graphify update .` 완료.
- 시뮬레이터를 재시작하고 기본 checkpoint CSV로 복원했다. 실행 중 planner/control은 최종 설치 바이너리와 일치하며 원본 checkpoint 파일은 변경하지 않았다. [복원 상태](restored_runtime.json)
- 진단 관측기만 종료했다. 추가 커밋·외부 게시·새 메시지 생성은 하지 않았다.
