# 로컬 경로가 짧아지는 이유: 실제 후보 전수 재생

저장된 실제 EgoStatus·DynamicStatus와 ego/global-route 이벤트를 사용해 **31개 상태**를 재생했다. 원본 경로가 발행된 **23개 모두 전체 waypoint 좌표가 일치**했고 최대 오차는 **1.207×10⁻⁶ m**였다. 실제 SearchTree가 저장된 **17개 상태**에서는 유효 후보 개수, 선택 인덱스, 모든 후보 길이가 일치했다(길이 최대 오차 1.85×10⁻⁶ m). 나머지 **8개 상태는 재생 유효 후보가 0개이며 해당 stamp의 실제 경로 발행도 없었다**.

분석 중 프로젝트 소스·설정·체크포인트 파일과 실행 중 planner를 변경하지 않았다. `/tmp/planner_census/`의 원본 소스 복사본에 기록용 필드를 붙여 탈락 후보도 보관했다. 후보 생성 수식, kinematic/velocity/collision 판정, 기존 비용 가중치는 유지했다. 전방 reference/허용 lane/goal을 바꾸는 비교는 **별도로 표시한 오프라인 실험**이다.

## 요점

경로가 짧은 이유는 서로 다른 단계에 있다.

1. **reference가 current+successor 하나에서 끝나므로 긴 후보가 처음부터 만들어지지 않는다.**
2. **경로는 reference 안에 있지만 차량 앞부분이 그 다음 정상 주행 lanelet과 겹쳐 긴 후보 전체가 forbidden으로 탈락한다.**
3. **50 m 이상 후보가 이미 정상 생성·검증돼도 immediate goal lane에서 멀어진다는 비용 때문에 11–16 m 후보가 선택된다.**
4. **reference가 충분해도 조밀하게 직선 보간한 waypoint에 대한 곡률 판정이 후보 대부분 또는 전부를 탈락시킨다.**
5. **교차로에서 footprint 면적만으로 교차 방향 lane을 current로 선택하면 heading 오차가 약 93°가 되어 후보가 전부 탈락한다.**
6. **빨간 신호의 0 m/s 구역으로 들어가는 긴 후보는 연속된 정지 waypoint의 ETA를 계산하지 못해 후보 전체가 탈락한다.** 따라서 충분한 reference가 있어도 19.68 → 13.57 → 9.11 m로 줄고 이후 유효 후보가 없어질 수 있다. 녹색 후 같은 구간에서 긴 경로가 다시 생성되어 재출발하는 사례도 확인했다.

전체 31개 상태의 원본 후보 **830개** 중 **465개 kinematic 탈락**, **104개 velocity 탈락**, **52개 forbidden-lane 탈락**, **209개 유효**였다. 초기 21개 상태에는 velocity 탈락이 없었지만, 추가 북쪽 신호 접근/정지 10개 상태에서 104개가 확인됐다. 이 표본에는 occupancy 충돌이나 collision 후 trim으로 끝나는 후보가 없었다. 이는 전체 운행에서 해당 단계가 문제 없다는 의미가 아니라, 조사한 사건들의 직접 탈락 원인이 달랐다는 뜻이다.

## 충분한 reference가 있어도 후보가 0개가 되는 이유

### 최초 주행의 (798.233,-85.692)

stamp **1789073545618980530**:

- current **28004**, reference **[28004,28075]**, 잔여 **103.681 m**.
- ego 속도 **2.319 m/s**, 초기 횡오차 **0.551 m**, heading 오차 **0.130 rad**.
- 15개 후보를 생성하지만 **15개 모두 kinematic 탈락**. 속도/occupancy 검사는 도달하지 않는다.
- 최초 탈락 위치의 곡률은 **0.172–0.504 m⁻¹**이고 제한은 **0.169492 m⁻¹**이다.
- reference/allowed/goal을 확장하는 A/B/C 모두 유효 후보 0개 그대로다.

곡률 판정에는 표현 방식 의존성이 확인됐다. 원본은 nominal **0.5초**마다 얻은 점 사이를 **0.5 m** 이하 간격으로 직선 분할한다. `kinematicallyFeasible`는 이 분할된 직선 segment 길이로 yaw 변화량을 나눈다. yaw 변화는 nominal segment가 만나는 한 지점에 몰리지만 분모는 작은 0.5 m segment가 되어 곡률이 크게 계산된다.

**좌표가 같은 직선 위에 있는 중간점만 제거해 polyline 모양을 유지**한 별도 수치 검사에서는, 원본에서 탈락한 15개 중 **9개가 같은 곡률 함수에서 통과**한다. 예를 들어 원본 candidate 2의 **33개 점 / 15.465 m** 경로는 **0.184720 m⁻¹**로 탈락하지만, 같은 polyline을 **5개 corner 점**으로 표현하면 **0.056214 m⁻¹**로 통과한다. 이것은 기하학을 바꾸지 않고 sampling만 바꿨는데 판정이 바뀌는 문제를 입증한다. corner만 남긴 경로가 물리적으로 안전하거나 충돌 검사를 충분히 수행한다는 주장은 하지 않는다. 이 비교 결과로 원본 pipeline의 탈락 판정을 바꾸지 않았다.

| Ego stamp | 상황 / 속도 | 원본 후보 판정 | 실제 선택 |

| 1789074614059163865 | 빨간 신호, 0 m/s | kinematic 25, velocity 평균 속도 0으로 5 탈락 | 없음 |

두 번째 정지에서는 첫 pose와 달리 **기하학적으로 통과하는 후보 5개가 이미 존재**하고, 빨간 신호의 속도/ETA 단계가 막고 있었다. 실제 신호가 **1789074616.700**에 녹색으로 바뀐 후 유효 후보가 생겼고, **1789074619.062**에 약 **3.53 m/s**로 정지선을 통과했다. 따라서 “빨간 신호에서 경로가 사라진다”와 “녹색에도 재출발할 수 없다”는 별개다. 정지 pose의 작은 차이가 kinematic 후보 존재 여부에도 영향을 준다.

녹색 두 경로의 원본 전체 좌표 최대 오차는 각각 **1.207×10⁻⁶ m**, **2.78×10⁻⁷ m**이고, SearchTree 유효 개수와 선택 인덱스도 일치했다. 이 표본의 미래 경로가 50 m를 넘는 현상은 기존 generation 길이 제한 초과가 남아 있는 결과다.

## 재현 범위와 자료

- 동적 상태: 저장된 실제 `DynamicStatus` CDR를 역직렬화했다. planner는 ego/dynamic을 독립 callback으로 보관하므로 실행 시 마지막으로 사용한 dynamic이 정확히 같은 stamp였다고 단정할 수 없다. 요청한 stamp **1789073777698673150**은 완전 동기 dynamic 파일이 없어 **239.522613 ms 전** 저장본을 사용했다. 나머지 선택 표본은 같은 stamp의 저장본이다. 실제 selected path 전체 좌표와 유효 SearchTree가 일치한 범위에서는 재생의 출력 동등성을 확인했다.
- goal/current: 실제 ego/route 이벤트를 순서대로 보내 원본 `IntersectionMonitor`와 `RouteUpdater::updateGoals` 상태를 재현했다. 이미 실행 중이던 첫 노드의 시작 전 상태는 직접 관측하지 못했다. 별도 남쪽/서쪽/북쪽 실험은 기록된 fresh-planner 시작 시각에서 상태를 초기화했다. 후보/선택 일치가 검증된 상태를 결과에 사용했다.
- 이 분석의 후보와 도로 경계 검사는 원본의 부분-overlap 허용, 고정 ego-Z, missing-cell 허용을 유지한다. 여기서 “유효”는 **원본 validator가 통과시켰다**는 뜻이다.
- 원본을 수정하지 않았으므로 graphify 갱신도 하지 않았다. 오프라인 probe는 ROS 토픽을 발행하지 않는다.
